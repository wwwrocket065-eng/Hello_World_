# Подпись релизов «Журнала разработчика» — обязательно
Последний подписанный релиз: **1.0.5**, `versionCode=6`, пакет `com.developer.journal`.
SHA-256 сертификата (публичный отпечаток): `b3bea82a722ec52f640de47f393529e222ff83cbe842cbaf520f3ca8dfed8bd7`.

**Никакие новые случайные ключи при сборке создавать нельзя.** Каждый новый APK необходимо подписывать именно этим сертификатом, иначе Android откажется обновлять приложение поверх версии 1.0.5.

Постоянный приватный ключ и пароль сохранены только в приватной библиотеке владельца:
- `/JournalDeveloper/private-signing/JournalDeveloper-release.p12`
- `/JournalDeveloper/private-signing/JournalDeveloper-signing-secret.json`

Не помещать приватные ключи или пароли в GitHub, коммиты, CI-логи, архивы с исходниками, публичные ссылки или пользовательские APK.

## Алгоритм выпуска
1. Читать `JOURNAL_RULES.md` и этот файл; использовать актуальные исходники в `developer-journal`.
2. Менять **только** согласованные пользователем части; не увеличивать книжку в самом приложении, не дублировать KV-кэш, не блокировать вертикальные свайпы.
3. Запустить `python3 developer-journal/tools/check_contract.py`, затем `gradle :app:assembleRelease`.
4. GitHub Actions намеренно публикует **неподписанный APK** и не выдаёт произвольный debug APK как готовый к установке.
5. В отдельной приватной среде импортировать ключ из пользовательской библиотеки и подписать release APK через штатный `apksigner` Android SDK (PKCS12), используя пароль из второго файла.
6. Проверить `apksigner verify --verbose --print-certs`; сравнить сертификат с указанным SHA-256; проверить `versionCode`, пакет, архив и изменённые файлы. При несовпадении **запретить публикацию**. Для релизного APK не использовать новый ключ.
7. Записать результат, версию, тесты и исключения в `DEV_NOTES.md`. Пользователю выдавать только подписанный APK.

Исторические сборки 1.0.1–1.0.4 были подписаны разными ключами. Перейти на закреплённый релиз 1.0.5 **поверх них невозможно**, если старый приватный ключ недоступен: требуется разовая переустановка с потерей локальных данных. После установки 1.0.5 новые сборки с этой же подписью смогут обновляться поверх.
