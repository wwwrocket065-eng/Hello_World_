> **Перед любой работой:** прочитать [PROJECT_RULES/REQUIREMENTS.md](PROJECT_RULES/REQUIREMENTS.md). Это обязательные требования к модульной архитектуре, патчам, UI и текущему порядку задач.\n\n# GlassStudy — обязательные архитектурные правила

1. Новая функция должна сразу предоставлять подписанный декларативный интерфейс настроек в modules/<feature>/config.json (версия схемы, проверка диапазонов, дефолты и миграция). Не добавлять одноразовые захардкоженные функции, если их параметры можно вынести в .pupdate.
2. Унифицированные окна: одна фабрика окон, общая тема, положение, поля, анимация (где поддерживается), закрытие по нажатию вне окна/назад/переключению другой панели. Никаких несвязанных AlertDialog с системной серой темой.
3. Все элементы UI должны опираться на одну систему цветов/скруглений/размеров и поддерживать патчи через доверенные JSON-конфигурации. Новые иконки/действия должны иметь заранее предусмотренные безопасные обработчики. Данные не должны исполнять произвольный код.
4. Стабильность: сначала совместимость старых ресурсов и подписанных патчей, затем миграция настроек, тесты, Gradle CI и только затем публикация. Не менять latest.json до готовности совместимого патча.
5. Одна ответственность на компонент: MainActivity — координация, SceneFloorGlb — геометрия, SceneModuleConfig — настройки, отдельный SceneDialog/UnifiedPopup — интерфейс.
6. Части, которые нельзя безопасно менять ресурсным патчем (DEX, разрешения, native API), должны иметь предусмотренные точки расширения. Когда нужен APK, это фиксируется явно; не обещать невозможного.
7. DEV_NOTES — причины ошибок и решения; тесты — поведение и проверка совместимости, а не хрупкий поиск случайных строк.
